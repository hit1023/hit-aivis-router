# 運用ガイド

## run.sh — 管理メニュー

`./run.sh` を実行すると対話メニューが起動します。

```
  ╔══════════════════════════════════╗
  ║     AIVIS Router  管理メニュー   ║
  ╚══════════════════════════════════╝

  1.  更新 & 起動     (pull → down → build → up)
  2.  ビルド & 起動   (down → build → up)
  3.  起動            (up -d)
  4.  再起動          (restart)
  5.  停止            (down)
  6.  ログを見る      (logs -f)
  7.  状態を確認      (ps)
  0.  終了
```

### 各メニューの使いどき

| 番号 | 使いどき |
|------|---------|
| **1. 更新 & 起動** | コードが更新された後（GitHubにpushされたとき）。`git pull` → リビルド → 起動を一括実行 |
| **2. ビルド & 起動** | `requirements.txt` や `Dockerfile` をローカルで変更したとき。pullは不要だがリビルドが必要な場合 |
| **3. 起動** | 「5. 停止」で止めた後に再開するとき。イメージは変わらないのでビルド不要 |
| **4. 再起動** | `.env` の設定値を変更したとき。コードは変わらないがプロセス再起動で設定が反映される |
| **5. 停止** | メンテナンスや一時的に止めたいとき |
| **6. ログを見る** | 動作がおかしいときのエラー調査、リクエストが届いているか確認（Ctrl+C で戻る） |
| **7. 状態を確認** | コンテナが起動しているか、いつから起動しているか確認 |

**通常の更新手順：** `./run.sh` → `1` を選択するだけで完了します。

## sync-aivis-data.sh — インスタンス間のデータ同期

同一ホスト上で `mm-aivis-router`（インスタンス1）と `mm-aivis-router2`（インスタンス2）を並行運用している場合に、データファイルを同期するスクリプトです。

### 使い方

```bash
# インスタンス1 → インスタンス2 に同期
./sync-aivis-data.sh 1to2

# インスタンス2 → インスタンス1 に同期
./sync-aivis-data.sh 2to1
```

### 同期されるファイル

| ファイル | 説明 | 備考 |
|---------|------|------|
| `compound_splits.json` | 複合語の表層形分割情報 | 自動コピー |
| `speaker_presets.json` | スピーカープリセット | 自動コピー |
| `text_replacements.json` | テキスト置換ルール | 自動コピー |
| `speech_history.db` | 発話履歴SQLite | **確認プロンプトあり** |

`speech_history.db` は上書きすると履歴が失われるため、コピー前に確認を求めます。

### 動作

1. コピー先のコンテナを停止（DBファイルの破損防止）
2. ファイルをコピー
3. コンテナを再起動

### 使いどき

- インスタンス1 → インスタンス2 へ切り替えるとき（最新データを2に反映）
- インスタンス2 → インスタンス1 へ戻すとき（2で登録したデータを1に反映）
